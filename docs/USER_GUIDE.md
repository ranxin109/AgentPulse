# 使用说明

## 一键启动

双击桌面的“一键启动任务组件”快捷方式。没有实例时启动组件，已有实例时尝试激活它；不会关闭或重启现有组件。没有任务也可以主动打开，显示空状态。安装目录的 `launch.cmd` 或 `ProgressWidget.exe` 也可启动。

快捷方式不依赖 Agent、桌面控制插件、Node 或浏览器。它直接指向原生程序；若安装目录被移动，需要重新创建入口。启动请求不能保证系统一定允许抢到前台。

组件按当前 Windows 桌面判断已有实例，避免隔离桌面里的进程拦住普通桌面。没有找到可显示窗口或启动失败时会给提示，详细信息保存在安装目录的 `launch-diagnostics.log`，不要上传含个人路径的日志。

重新创建：运行 `create-shortcut.ps1 -WidgetPath '实际组件路径\ProgressWidget.exe'`。安装时默认创建桌面快捷方式，可用 `-SkipDesktopShortcut` 跳过。

## 列表与详情

列表没有大标题、任务总数或常驻历史按钮。每张卡片主要显示任务名称、进度条与已耗时，长标题会随宽度换行；完整需求和问题在详情中查看。任务多时可用滚轮滚动，列表隐藏系统滚动条。

执行中正常为蓝色；已完成为绿色；暂停等待用户确认或授权时为橙黄色“待确认”。active/waiting 超过 `max(120 秒, 2 × report_interval_seconds)` 没有新上报时变红，待确认不因超时变红。红色可能表示信息过期，也可能是 Agent 明确报告 failed；详情说明原因，不把超时自动视为失败。

点击卡片进入详情，查看需求、总体进度、当前问题、使用模型、最近上报以及每个阶段的状态、预估、耗时和完成时间。点击返回箭头或按 Esc 回到列表。预估可选，未提供时明确显示未提供。模型信息由 Agent 填写，组件不能自行识别真正的模型版本。

组件读取当前屏幕工作区并限制详情窗口，避免内容因窗口越界而遮挡；长内容在详情内滚动。

### 没有任务时

无任务时显示小图标、“暂时没有任务”及“新任务会自动显示在这里。右键可查看历史或关闭组件。”；全部已阅后显示“任务已全部确认”。历史为空显示“暂无历史记录”，数据异常显示“任务读取异常”，不冒充正常空状态。窄窗口时说明自动换行。

组件始终保持打开，即使任务全部完成、清空或聊天结束，也不会由 Agent 自动关闭。关闭由你通过右键菜单操作；更新需要退出时也由你自行关闭。圆环没有未完成任务时显示横线，不显示虚构的 100%。

## 完成、排序和历史

主列表按任务创建时间倒序显示，最新在上、最早在下，已完成和未完成使用同一排序规则。创建时间优先使用 created_at，旧数据回退到 started_at。任务更新或完成不会改变位置。点击完成卡片的圆形确认按钮后，整张卡片置灰并禁止点击，等待约 3 秒后播放退场动画；任务进入历史，数据文件仍保留。

主列表使用固定时间排序，旧的手动排序记录不再影响顺序，也不提供长按拖动改序。新任务仍以插入动画出现。历史按已阅时间倒序显示。

右键空白区或卡片打开菜单：历史记录、固定（始终置顶）、调整大小和位置、最小化显示、关闭组件，以及一键确认所有已完成任务、一键清理故障任务。卡片菜单另有删除任务，需确认后移入回收站。批量操作范围与保护规则见 [BULK_AND_CONFIRMATION.md](BULK_AND_CONFIRMATION.md)。

## 列表大小与位置

右键选择“调整大小和位置”进入编辑模式，临时显示移动、缩放、保存、取消控件。正常模式锁定列表位置和尺寸。

列表实际高度按当前卡片内容自动计算：一个任务就收紧到一张卡片，任务增加时逐渐增高，到上限后滚动。空状态同样保持紧凑。宽度沿用用户设置；手动保存的高度作为列表高度上限，默认上限 540 屏幕像素，不强迫少量任务撑满上限。进入详情时独立扩展阅读高度，返回列表重新收紧。

拖动移动控件改变位置；拖动缩放控件或允许的窗口边缘改变宽高，内容按宽度重新排版。碰到当前屏幕工作区边缘时即停止，不能继续越界；拖动过程中限定在开始操作的屏幕内。点击保存持久保存；取消回到进入编辑前的位置和尺寸。

## 最小化圆环

右键“最小化显示”进入圆环。它选择当前队列中第一个未完成、未阅任务，跳过已完成任务。中心显示百分比；没有未完成任务时显示横线。正常为蓝青渐变，过期/失败为红色渐变，待确认为橙黄渐变。圆环不自动按时间增加百分比。

- 左键直接拖动圆环改变位置，无需先进入菜单。
- 在圆环上滚动鼠标滚轮改变大小，每步约 4 个逻辑像素，允许直径 44–128 个逻辑像素。实际屏幕像素随系统缩放变化。
- 圆环右键“调整大小和位置”保持圆环形态，开启右下边缘拖动缩放。
- 移动或缩放操作结束即自动保存，不需要再按保存。
- 取消最小化后，先按当前任务数量计算紧凑高度，再靠近圆环展开：右侧/下方有空间时贴近圆环左上位置，空间不足则朝左/上展开，并限制在屏幕内。不会再用旧的大窗口高度把单任务列表推远。
- 下次进入圆环时读取保存的位置和大小。重新启动组件默认进入列表，最小化模式本身不跨进程保存。

## 文件与故障处理

|文件|内容|
|---|---|
|`tasks/*.json`|每个任务的状态；已阅也在这里|
|`window.json`|列表位置与大小|
|`list-height-limit.txt`|用户保存的列表高度上限|
|`compact-window.json`|圆环位置与直径|
|`queue-order.json`|未完成任务的手动顺序|
|`pinned.txt`|置顶选择|

任务进度不动：查看最近更新时间与当前问题，由任务所属 Agent 上报；不要把任务年龄当成完成证据。组件没有自动发现所有 Agent 的接口。

组件未出现：先确认安装路径和数据目录；Agent 有桌面工具时应截图检查。进程存在不证明用户能看见窗口。不要循环启动多个实例，更不要为修复组件而结束其他无关应用。

数据无法写入：给 Agent 授予对应任务目录的写权限，或用可写目录，并让组件读取相同目录。损坏 JSON 需要从已知快照修复，不应默默覆盖。
